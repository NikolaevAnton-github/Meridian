# Tripo Studio research for PlayerCharacter01

Verification date: 2026-09-17. Scope: official public Studio pages, product/help documentation, release notes, pricing and terms, supplemented by the controller's limited live observation below. This research did not upload a model, generate an asset, purchase anything, call a paid API or install a DCC bridge. Features below are documented or publicly visible; output quality and the owner's precise feature entitlements remain untested.

Controller-supplied live observation from the same research session: the owner's workspace exposes Model, Segment, Fill Parts, Retopo, Texture, Edit, Upscale, PBR and Animate; Smart Mesh is labeled P2.0 Preview and Private is selected. A pre-existing generation was at 99% and was left untouched. This supplements the public-document review; it is not a generation or export test, and no account balance is recorded here.

## Pipeline conclusion

Tripo is a useful candidate for generating the protagonist's initial volume and separate armor components, then refining parts before export to Blender. It cannot yet be called a verified final-character solution for this project. The first useful experiment is a bounded geometry comparison using the existing original concept references, followed by inspection of silhouette, armor separation and articulation areas. A low polygon count, quads and automatic skinning are separate properties; none alone establishes suitability for first-person arms or rifle handling.

Use a shared full-body proportional reference and selectively separate rigid equipment. Do not independently generate every limb and expect matching anatomy, scale, joints or hidden interfaces. This is a project recommendation, not a Tripo product guarantee. Existing owner concept-selection and modeling gates are unchanged by this research.

## Four operations that must not be confused

1. **Generate in Parts:** one generation returns segmented output. It is not evidence that individually generated armor pieces will fit each other.
2. **Segmentation:** partitions existing visible geometry into editable pieces; it does not establish a complete suit underneath armor.
3. **Completion:** proposes geometry for missing regions of segmented pieces. The output may need thickness and clearance correction.
4. **Assembly:** establishes proportions, transforms, interfaces, hierarchy, shared skeleton and collision/deformation behavior. This is our Blender production responsibility, even when Tripo supplies transforms and named parts.

The first three descriptions follow the [Studio tutorial](https://www.tripo3d.ai/blog/tripo-studio-tutorial-english), [segmentation feature](https://www.tripo3d.ai/features/ai-model-segmentation) and [completion explanation](https://www.tripo3d.ai/blog/ai-complete-missing-parts-after-3d-model-segmentation). The assembly conclusion is a project inference from the required game behavior, not an advertised Tripo limitation.

## Account, credits and Blender routes

**Studio credits and API credits are separate.** A paid Studio subscription supplies monthly credits that do not roll over. It does not authorize using those credits through an API key; API purchases are separate. [Explicit billing distinction](https://www.tripo3d.ai/help/api-plugins/tripo-studiotripo-api)

The public pricing page currently lists Free, Pro, Max and Team. Pro advertises 3,000 monthly credits, private commercial models, 7-day history, DCC Bridge and the advanced production toolkit. Max advertises 25,000 credits, permanent history and unlimited access to 8K texturing. The displayed amounts/cycle labels contain annual/monthly and promotional presentation, so this report does not infer the owner's paid tier or effective price. Individual feature checkmarks are partly lost in public text extraction. [Pricing](https://www.tripo3d.ai/pricing)

There are two different Blender-related routes:

- **Studio DCC Bridge:** the specific bridge guide describes browser-to-Blender transfer of already generated models. It lists Windows/macOS, Blender 4.1+, Chrome/Edge 116+ or Opera 102+. Default transfer recenters the pivot to center-bottom and does not pack UVs. [Blender Bridge guide](https://www.tripo3d.ai/blog/tripo-dcc-bridge-for-blender)
- **Generation plugin/API integration:** the help article instructs configuring an API key and having API credits. [DCC plugin help](https://www.tripo3d.ai/help/api-plugins/dcctripo)

Do not install the API generation route expecting Studio credits to work. Manual GLB/FBX export is sufficient for an initial trial and produces explicit local evidence. A bridge is optional convenience; verify the actual plugin version, connection and part origins before adopting it. No bridge was installed or tested here.

## Commercial use and privacy

The currently served Terms were last updated July 11, 2025. Section 5.2.2 grants paid-user rights subject to the terms, reserves a service-provision license to Tripo, and says paid Inputs/Outputs will not train, validate, test or improve AI technology. Section 5.2.1 gives Tripo broad rights over free-user Inputs/Outputs. The terms do not guarantee uniqueness or non-infringement. [Terms](https://www.tripo3d.ai/terms)

Commercial game use is explicitly allowed for paid-generated assets in the official simplified guide, with input-image rights still the user's responsibility. Do not assume subscribing retrospectively fixes the rights of old free outputs; that case was not conclusively established here. Preserve generation date and paid status with the output provenance. [Commercial use help](https://www.tripo3d.ai/help/privacy-policy/how-to-use-tripo-models-commercially)

The asset help distinguishes Private, Public and Share Only, and says other users cannot access Private models through the platform. This is an access setting, not zero processing or zero retention. [Asset privacy help](https://www.tripo3d.ai/help/privacy-policy/is-my-asset-safe)

The privacy policy dated February 5, 2025 covers uploaded content/metadata, provider processing, analytics and international transfers, and offers account-deletion requests. It does not establish a project-specific guaranteed deletion deadline. No claim of local-only processing or guaranteed confidentiality is made here. [Privacy policy](https://www.tripo3d.ai/privacy)

## Required first-trial observations

Before using existing subscription allowances, record the actual account plan, renewal date, remaining credit pool, private setting, selected model version and per-action quote. Check whether Generate in Parts is available with the chosen multiview/mesh mode. A practical initial route is eligible unrigged geometry, segmentation/boundary correction, selective completion, then retopology. A separate native-quad generation can be evaluated directly in Blender without routing through Tripo segmentation.

**Order constraint:** Tripo segmentation must precede quad conversion and rigging under the publicly listed restrictions. Do not generate final quads or apply Auto Rig and only then discover that armor must be split. Save the eligible unrigged geometry first. If P2.0 Preview cannot combine the required part generation with the selected topology mode in the owner's UI, choose an eligible triangle/high-detail source or perform separation in Blender; do not repeatedly spend credits trying an unsupported sequence.

Compare four orthographic silhouettes and close views of helmet, plate borders, shoulders, elbows, knees, wrists and hands. Test import scale/origins, object separation, UV/maps and material boundaries. After provisional fit, bend elbows/knees, raise shoulders and grip a rifle proxy; inspect flexible-suit pinching and armor intersections. Record human repair time as well as credits. These project acceptance checks determine usefulness more reliably than a rendered turnaround.

## Evidence conflicts and limits

- Generic help says up to 50K quads; the dedicated current Smart Mesh page and P2 release agree on **25K quads / 50K triangles**. Use the specific limit and check the UI.
- The older tutorial calls importing local models coming soon; current workspaces and help expose it. Use the current pages.
- Marketing says any creature-like rigging; explicit import help narrows supported inputs. Assume the narrower support until a result proves otherwise.
- One animation-ready help article mentions OBJ with rigged output. Do not rely on that wording for skeleton preservation; the dedicated rigging and multiple-animation pages specify FBX/GLB.
- Marketing promises reference precision, clean topology and no cleanup. Those statements are vendor claims, not test evidence for our character. Different input views can still contradict one another, and occluded interiors remain inferred.
- No generated asset, exported skeleton, finger test, character-specific UV evaluation, service credit deduction or Blender/Unreal round trip has been performed by this research. The controller's limited existing-workspace observation is listed above.

The report is a documented capability assessment and proposed integration path, not production modeling approval or acceptance of a generated character.
