# ED-04: Second material response and repeatable specimen authoring

Multica issue: **MSQ-144**. Parent: [EnvironmentDestruction01 / MSQ-74](../EnvironmentDestruction01.md).
Draft prepared 2026-09-24; prepared only, no implementation dispatched.
Follow the [execution plan](../EnvironmentDestruction01Plan.md) and
[owner authority](../../Approvals/EnvironmentDestruction01-LobbyLab01.json).

## Objective and dependencies

After [ED-03](ED-03.md), add a second explicitly selected reusable nonstructural
object with a meaningfully different material/physical response. Both objects use
the same bounded authoring/runtime contract and the same copied lobby map.

Use the ED-00 inventory and record the second source, dimensions, material and
cover/cosmetic role before production. A different tint alone is insufficient.
No second suitable source means a bounded selection issue; it does not authorize
new art, paid assets, glazing refinement or wall damage.

## Work and deliverables

- Produce task-owned derived assets for the second object. Preserve source meshes,
  shared materials, owner geometry and retained acceptance records.
- Reuse local accumulation, attachment/fracture, collision revision, support and
  cleanup behavior. Keep the material distinction in explicit tunable data where
  practical: thresholds, fragment shape/scale, mass, impulse and attachment rules.
  Explain which simplifications are artistic/physical tuning.
- Make one concise authoring recipe with required source suitability, derived
  package ownership, tuning fields, placement/reset steps and validation checks.
  Resolve the duplication exposed by two real specimens; do not build an open-ended
  asset framework or add an unrequested object library.
- Record both specimen identities and instance limits in a shared lab manifest
  ready for progressive placement in ED-05. New impact polish remains ED-06.

## Acceptance and evidence

- Actual rifle hits produce local damage and a material-appropriate difference
  between the two specimens. The second object's solid regions and holes agree
  with collision, and its disconnected portions behave according to its stated
  attachment model.
- Both instances coexist without sharing mutable damage state or reset ownership.
  The second specimen respects the existing debris/support/cleanup contract.
- An additional instance made through the recipe works without unique code or
  edits to the source asset. This is a focused scalability check, not a new family
  of production objects or a blanket repetition of all previous checks.
- Preserve applicable evidence for the first specimen and recheck only behavior
  changed by shared implementation. Record authoring effort and per-instance cost
  observations without inventing an FPS target.
- Save comparable views, focused checks, the authoring recipe and identity under
  `Saved/EnvironmentDestruction01/ED-04/<Candidate>/`. Identify commit/dirty scope,
  map/actors, both source and derived package fingerprints, tuning, runtime/worker
  settings and evidence runs.

Apply the plan's primary technical review and applicable visual review route.
Owner judgement of appearance remains separate from technical acceptance.
