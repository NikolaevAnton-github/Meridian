# ED-05: Progressive lobby population and measured quality-preserving tuning

Multica issue: **MSQ-145**. Parent: [EnvironmentDestruction01 / MSQ-74](../EnvironmentDestruction01.md).
Draft prepared 2026-09-24; prepared only, no implementation dispatched.
Follow the [execution plan](../EnvironmentDestruction01Plan.md) and
[owner authority](../../Approvals/EnvironmentDestruction01-LobbyLab01.json).

## Objective and dependencies

Using [ED-04](ED-04.md)'s two specimens and [ED-00](ED-00.md)'s baseline, gradually
populate `/Game/Maps/L_OpeningLobby_DestructionLab01` through sparse, representative
and bounded dense configurations. Measure cost as density and active destruction
increase, then tune demonstrated bottlenecks while retaining the intended quality.

## Work and deliverables

- Use removable instance groups or equivalent recorded configuration in this one
  map. Define and record object counts, placement/route, expected simultaneous
  damage and live-fragment limits for each density before measuring it. Progress
  only after the preceding configuration is understood. Dense means a declared
  bounded stress case, not complete architectural destruction.
- Keep source geometry, scale, lighting/material direction and owner assets intact.
  Populate only selected objects; do not expand into walls, columns, floor, ceiling,
  storefront work or new layout design. Preserve usable routes in the declared
  representative configuration.
- Reuse the baseline route, views, resolution, quality settings and capture method.
  Compare intact, active-fracture and settled-debris windows at each density on the
  verified local hardware. Capture CPU/game/render/GPU timing where available,
  spikes/P95, physics cost, live bodies/fragments and memory, with window duration,
  repeatability limits and editor/runtime overhead stated.
- Identify the limiting work before changing it. Tune bounded activation, collision,
  sleep, cleanup, asset data or other measured causes. Keep local damage detail,
  hole truthfulness, material/silhouette quality, meaningful support and visible
  debris response. Do not lower resolution/quality, hide missing destruction or
  disable all debris collision to make a timing comparison appear successful.
- Preserve named before/after candidates and comparable views for each material
  tuning change. Record unresolved performance/quality tradeoffs for the owner;
  hardware identity is not evidence of an achievable FPS target.

## Acceptance and evidence

- All three configurations are reproducible in the same copied map. A concise
  table reports actual count/load and timings against ED-00 and the preceding stage.
- The representative route remains usable; active destruction and repeat resets
  stay bounded. Focus on behavior newly exposed by density, not a full replay of
  earlier isolated tests.
- Each claimed improvement has comparable measured evidence and retained visual/
  collision/support quality. Independent visual judgement uses actual comparable
  views; technical timing does not grant owner visual or play acceptance.
- Store layout manifests, raw captures, selected traces/views and analysis under
  `Saved/EnvironmentDestruction01/ED-05/<Candidate>/`. Identity includes commit/dirty
  scope, lab map and assets/fingerprints, active configuration/tuning, hardware,
  runtime and actual worker settings. State remaining limits without an FPS promise.

Follow the plan's primary technical review and focused finding-closure route.
