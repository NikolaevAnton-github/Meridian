# DestructionPerf01 / DP-02: controlled isolation experiments

Status: **prepared; execution not started**. Dependency: DP-01.
Read the [shared scope and measurement contract](../DestructionPerf01Tasks.md).
Plan coverage: [section 2](../DestructionPerf01Plan.md).

## Outcome

Rank actionable changes by demonstrated cost and preserved destruction outcome,
then route each result to DP-03 through DP-08. Stop experiments once attribution
is sufficient; completing every diagnostic row is not a goal.

## Bounded work

- Use DP-01's reference and reversible switches or versioned test candidates.
  Change one factor, run paired comparisons, then restore the reference between
  experiments. Never restore historical bytes over owner edits.
- Select comparisons from the measured hypotheses: break VFX off; break/collision
  sound off; optional material switching bypassed; fragment rendering hidden;
  small-debris collision policy; reduced tiny rigid fragments in a derivative;
  simplified field commands with equivalent intended damage area.
- Reuse the existing Niagara diagnostic as evidence: it did not remove the warm
  CPU limit. Repeat only for a changed candidate or a specific unresolved cost.
- Record frame/task differences and body/contact/event/effect counts alongside
  damaged actors, openings, major chunk trajectories and presentation changes.
- Keep diagnostics distinct from candidates. Invisible fragments, weaker motion
  or absent effects do not become the shipped optimization by passing a timer.

## Acceptance and focused verification

- Paired phase results include repeated-run variability and workload identity.
  Adopted hypotheses have improvements above noise and an explained causal link.
- Similar damage is verified; fewer affected props or a smaller blast cannot be
  reported as an equivalent-load performance gain.
- The ranked result identifies event/profile, presentation, fracture/contact,
  lifecycle, field/release and representation branches as actionable, conditional
  or unresolved. Include what additional evidence would resolve an unknown.
- Diagnostic switches are reversible and absent from the normal candidate by
  default; reset still restores the reference after a modified experiment.

## Handoff and limits

Record paired timing/effect tables and branch priorities here. Preserve raw runs,
candidate identities and rejected experiments in `Saved/DestructionPerf01/DP-02/`.
This task may prepare temporary diagnostic derivatives, but makes no final art,
gameplay, production-budget or optimization-acceptance decision.
