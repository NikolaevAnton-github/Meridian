## Outcome

Rank actionable changes by demonstrated cost and preserved destruction outcome,
then route each result to DP-03 through DP-08. Stop experiments once attribution
is sufficient; completing every diagnostic row is not a goal.

**Result:** the batch diagnostic reduces warm burst p95 from **155.16 to 46.66 ms
(69.9%)** on the same build/workload. Trace evidence attributes a large reduction
to repeated profile application while substantial task waits remain. Every vendor
break callback is forwarded and the same ten core props break, but early movement,
presentation timing and individual openings differ. DP-03 is the first actionable
branch; no diagnostic is adopted as the normal gameplay optimization.

## Experiment setup and rejected instrumentation

The initial DP-02 snapshot matches all 489 DP-01 asset/config hashes, including
the three pre-existing owner edits. The editor was closed. The retained map,
400 cm fixed blast, camera, graphics and source assets remain the reference.

The current vendor Blueprint was exported read-only under
`Saved/DestructionPerf01/DP-02/current-blueprint-readonly-20260929-184641-122997/`.
Its SHA-256 is `9854e46577cba825b13f774b716f7ea449b4c38863bb690a76b86cba5be043da`.
The break callback executes material switching, break FX and break sound, then
sets `IgnoreCharChaos` on `BreakEvent.Index`. The collision callback repeatedly
sets that profile on literal index 0 when speed exceeds 0.5 cm/s. It also owns
collision sound and a four-second retriggerable collection-sleep delay after
speed exceeds 200 cm/s. Removing that callback therefore changes sleep behavior;
it is not a clean equivalent-load optimization or an isolated audio test.

The first native-UFunction interception route is rejected. `dp02_observe01` has
four complete captures but zero intercepted calls. Passive probes and a native
debugger confirmed an installed function pointer; the configured component lookup
and two vendor script pointer occurrences referred to that same UFunction. They
did not establish usable dispatch through the interceptor. No speedup is inferred
from these runs. Native-hook source, failed/diagnostic runs and comparator rejection
are preserved under the DP-02 evidence directory. Debugger probes are excluded
from timing comparisons; all agent breakpoints were removed and user breakpoints
were untouched. `current-blueprint01.log` contains a commandlet that completed
without producing disassembly; the later raw-node export supplies current graph
evidence instead.

The replacement experiment uses a per-component break-event bridge: an immediate
forwarding control, then an end-of-frame batch that first applies the verified
profile to the exact queued break indices and replays every original vendor break
callback. Collision callbacks and native adapter notifications remain in place.
This is a diagnostic scheduling change; cross-actor ordering and presentation
latency need explicit qualification before any production adoption in DP-03.

The bridge leaves the native adapter break binding installed. It validates the
vendor class and the single scripted break callback's signature before replacing
that binding. Batch preapplication uses a deduplicated set of the actual received
bone indices and `IgnoreCharChaos`; it forwards every queued original callback in
per-actor order. Original material, FX and sound code still executes. Original
profile-setter calls also still execute and can skip already-identical values.
Bridge counts therefore do not measure saved native setter calls.

These switches are standalone diagnostics with `reference` as the default. Normal
gameplay creates no bridge. Reset flushes, restores saved delegates and destroys
the transient bridges before recreating props; the next repeat installs fresh
bindings. The comparator checks exact capture/manifest identities, explicit allowed
mode differences, reset ordinals, switch liveness and empty pending queues. It
rejects a configured-but-unexercised switch before producing timing deltas and
never promotes an identity match into equivalent destruction or acceptance.

so replayed original setters can observe already-identical state. Combined source,
switch-liveness and trace evidence support that mechanism. Changed-profile counts,
`LoadCollisionProfiles` calls and filter submissions are not directly instrumented.
