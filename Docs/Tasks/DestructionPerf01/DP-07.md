# DestructionPerf01 / DP-07: measured field and release optimization

Status: **prepared; execution not started**. Dependency: DP-02.
Read the [shared scope and measurement contract](../DestructionPerf01Tasks.md).
Plan coverage: [section 5](../DestructionPerf01Plan.md).

## Outcome

Reduce measured blast-delivery or body-release cost while retaining the intended
damage envelope and immediate impact, or record why the current path should stay.

## Bounded work

- Confirm live strain, radial/directional velocity, torque, falloff, affected-object
  filter and command lifetime. Historical vendor DSL exports are navigation aids,
  not proof of current settings or installed-engine API availability.
- If DP-02 attributes material cost to fields, compare simpler bounded commands
  or targeted strain/velocity application. Avoid duplicate delivery and needless
  wakeup of retired cosmetic debris; preserve required interaction with rubble.
- Cache immutable configuration/lookups only when recurring setup work is measured.
- If release bursts dominate, evaluate supported cluster/release throttling in
  the installed engine. Measure released bodies per frame and the added latency
  from blast to visible/physical break, including worst cases.
- Keep variants versioned and compare independently before combining them. If
  neither path is significant, provide the evidence-backed retain-current decision.

## Acceptance and focused verification

- Affected actors, radius, local holes, substantial impulses and impact timing
  remain consistent with the reference; a weaker/slower blast is not a free gain.
- F6 cancels pending delivery/release work, and subsequent blasts and rifle hits
  operate on the current generation rather than stale targets.
- Check normal speed and a controlled slowdown case for changed scheduling, with
  real-time cost and simulation-time latency reported separately.
- Adopt only a repeatable benefit above noise, documenting tradeoffs. Do not hide
  a hitch through unacceptable delayed destruction or reduce global physics quality.

## Handoff and limits

Record adopted configuration/code or the retain-current decision here, including
measured latency and remaining constraints. Store traces and comparisons under
`Saved/DestructionPerf01/DP-07/`. DP-05 owns fracture recipes; DP-06 owns debris
lifecycle. Coordinate their resulting contracts without assuming they are already
implemented or reviving retired custom destruction.
