## Outcome

Show what destruction density the integrated candidate supports under actual
gameplay, identify remaining limits, and deliver a reproducible candidate for
owner testing. A high-end-machine result alone cannot close the production target.

## Bounded work

- Record the agreed target hardware, representative scenes and frame/burst budget.
  If these remain undecided or unavailable, complete useful current-machine
  measurements but explicitly leave production performance acceptance open.
- Run controlled 1/2/4/8 affected-prop cases plus the retained ten-central-pillar
  reference. Record actual damaged props and secondary damage separately from
  configured primary count; use equivalent graphics and workload definitions.
- Include close/distant views, successive blasts into fresh/scattered debris,
  multiple active damage areas, sustained available AI/rifle gameplay and late-
  session memory/cleanup. Do not implement unrelated AI successors to fill a test.
  State the active AI baseline and any unavailable representative combat case.
- Exercise normal time and canonical slowdown, including changes of time scale
  during effects/release/retirement and F6 reset while work is pending. Use a
  documented repeatable slowdown workload; F7 currently rejects slowdown arming.
- Reuse DP-01's phase/counter procedure, including warmed repeats and an untraced
  control. Record real-time cost independently from simulation-time progression.
- Verify an appropriate packaged Development build before production claims.
  Compare against the reference and correct measured regressions in the owning
  task/preset, then rerun only the affected checks.

## Acceptance and focused verification

- The regression matrix covers performance, visible damage, bullet/player/cover
  collision, follow-up impacts and reset. Resource counts stabilize across cycles.
- Report phase median/p95/p99/max and blast hitches. Assess the proposed p95 <=
  8.33 ms and repeated > 16.67 ms criterion honestly, listing all excursions;
  slowdown cannot pass by observing less destruction in the real-time window.
- State supported workload limits, improvements, failures and remaining tradeoffs
  with exact candidate identity. A failed target remains failed, even when an
  intermediate optimization is useful; do not relabel it as acceptance.
- Final gameplay/visual quality and acceptance belong to the owner. Distinguish
  completed technical verification, unresolved production targets and owner verdict.
