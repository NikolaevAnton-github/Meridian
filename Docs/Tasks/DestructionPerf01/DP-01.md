## Outcome

Explain the blast hitch and sustained slowdown by phase, with enough workload
identity and counters to compare later candidates fairly. Extend the delivered
measurement tools only where necessary; do not rebuild the existing fixture.

## Bounded work

- Check the live asset/configuration against the recorded baseline, preserving
  owner edits. Name a fresh reference if those edits change the workload.
- Reuse the fixed position, camera, radius, F6 reset and native recorder. Add
  explicit start/blast/phase/completion markers and the missing phase summaries.
  Preserve old captures and their original phase definitions.
- Capture CPU/frame/task and GPU timing supported by the installed engine. Trace
  wait dependencies through worker execution; distinguish field evaluation,
  breaking/body release, contacts/solver, synchronization, event/Blueprint work,
  Niagara, audio, rendering and GC. Add narrowly scoped diagnostics only as needed.
- Record newly released and active/sleeping bodies, contacts, break/collision
  events, Niagara instances, audio voices and allocation peaks where available.
  Use actor path plus adapter ID; copied vendor ObjectId values are insufficient.
- Separate cold startup and at least three warmed runs. Keep an untraced control,
  quantify tracing overhead, and retain real-time and simulation-time origins.
- Measure intact CPU/GPU/memory costs and propose separate destruction/burst
  allowances. Record target-hardware/scene decisions still needed; their absence
  does not prevent attribution on the existing measurement machine.

## Acceptance and focused verification

- The current untraced slowdown is reproduced under a documented workload; traces
  reproduce it closely enough to support attribution, with overhead disclosed.
- Phase median/p95/p99/max and blast-frame costs are available. Ranked dominant
  stacks/tasks account for a material measured cost; unresolved generic scopes
  remain explicitly unattributed rather than assigned to Chaos or Blueprint.
- Counter availability and units are stated. Break counts are not body counts,
  and inclusive/nested/parallel times are not summed into fictional frame costs.
- Confirm F7/F6 behavior only if the harness changes it. Use focused analyzer
  checks for changed phase/timing calculations and a build if code changes.
