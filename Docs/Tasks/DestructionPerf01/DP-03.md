## Objective

Reduce redundant collision-profile writes and gameplay notification fanout while
preserving every required collision state transition and consumer-visible change.
The warm first five seconds contain 452,570 collision callbacks and 357,503 profile
changes: 0.668394 s inclusive callback time and 0.256371 s exclusive profile time.
These nested timings must not be summed or treated as the full recoverable cost;
GameThread task waits also total 2.096303 s in that interval. See the
[baseline evidence](../DestructionPerf01.md#isolation-and-trace-evidence).

## Bounded work

- Use DP-02 results to identify identical repeated writes and the consumers of
  adapter collision-change publications before changing either path.
- Define a project-owned deduplication policy for the complete desired profile
  state. Skip a write only when the current state is demonstrably identical.
- Keep cache identity valid for actor path, adapter identity and particle lifetime;
  copied `ObjectId` values alone are insufficient. Invalidate on reset/recreation.
- Batch collision-change publication once per affected actor/frame only where
  consumer contracts permit it. Preserve complete changed bounds, required
  revision semantics, ordering and reset identity across the batch.
- Retain required gameplay break/collision callbacks, collision transitions and
  sleep/wake behavior. Do not drop gameplay callbacks to reach a frame budget.
- Count raw callbacks, requested/applied/skipped-identical profile writes, pending
  and published changes, and reset invalidations; retain actor-level attribution.
- Keep presentation selection, VFX/audio quotas and optional material-switch
  deduplication in [DP-04](DP-04.md); body/contact policy remains separate work.

## Acceptance and verification

- Compare each adopted change independently using DP-01/DP-02 controls, including
  the warm first five seconds and common phase statistics. Improvement must exceed
  run variability; report any unchanged limiting work and unavailable counters.
- Verify equivalent affected actors, major openings, useful cover, bullet collision
  and traversal. Event counts are not active-body counts or proof of equivalence.
- Exercise multiple changes within one frame, multiple actors with copied IDs,
  reset with a pending batch, and subsequent damage; show complete bounds, valid
  revisions, no stale publication and no missed required gameplay notification.
- Verify focused source/build checks and applicable runtime checks when execution
  is authorized. Owner testing and final gameplay acceptance remain required.

## Implementation and branch decisions

`UDestructionCollisionPolicy` handles the verified vendor collision graph's
straight-line branch natively when speed is <=200 cm/s. It stores the same
`CollisionInfo` and requests `IgnoreCharChaos` on bone 0 only above 0.5 cm/s.
Every event above 200 cm/s still calls the original Blueprint synchronously:
sound selection, random calls, gates, retriggerable four-second sleep delay and
its original latent owner/phase are unchanged. All break callbacks remain original.
No presentation quota, material change, damage/field change or asset derivative
is introduced.

The guard reads the actual component's protected override array through a
type-safe base-member pointer: no downcast, guessed offset or last-request cache.
Only an initialized array of the current rest-collection transform count with
the exact current bone-0 profile skips a setter. Different state reaches the
engine setter immediately, including its game-thread query and physics-thread
filter updates. Actor/ObjectId copies cannot alias this policy. External writes,
same-component physics recreation and replacement actors are tested.

The installed UE setter already deduplicates identical overrides. DP-02's large
burst gain came from batching different break indices and deferring callbacks,
not from finding hundreds of thousands of actual filter transitions. That
diagnostic is **not adopted**: `LoadCollisionProfiles` updates scene-query filters
synchronously, and holding a scoped profile transaction until frame end leaves
queries stale between callbacks. Public Chaos handler registration does not
provide a guaranteed ordered pre/post batch boundary. Details and exact engine
source references are in `Saved/DestructionPerf01/DP-03/profile-path01.md`.

Compatibility requires the exact source Blueprint fingerprint, a clean compiled
loaded Blueprint, its single known collision binding and matching property schema.
Unsupported or cooked/unverified artifacts retain the original vendor callback.
This delivery targets the existing Development Editor gameplay setup; packaged
validation and a cooked-artifact compatibility contract remain later work.

Notification batching is implemented as a **retained opt-in experiment**, with
an explicit batched subscription, complete union of every changed envelope,
first/final revision and change count, actor/adapter/collection paths and a
world-local lifetime token. Legacy subscribers and `LatestChanges` stay synchronous.
The new actor-keyed cache separates copied IDs. Reset consumes pending bounds,
cancels the old publication and advances identity; same-component physics
destroy/create also advances identity. Reentrant callbacks cannot publish a
retired lifetime, and retired actor cache entries are removed.

Batching reduced publication count but did not improve this fixture's timing;
there are no bound legacy consumers in the measured scene. Normal delivery
retains immediate notifications. The prepared batch remains available for a future
measured consumer workload, with its tests and rejected timing evidence preserved.

## Measured decision

Adopt **native collision handling with immediate notifications**. Normal launches
use that combination. `-DestructionCollisionMode=vendor|observe|native` selects
the original control, instrumented original handler or hybrid candidate.
Standalone `-DestructionNotificationMode=immediate|batch` selects notification
delivery; PIE retains immediate delivery. The measurement launcher deliberately
defaults to vendor/immediate and records both explicit modes in its manifest.

### Counters and causal trace

Across the three native warm first-five snapshots, 604,184-612,381 raw collision
events equal native-fast plus synchronously forwarded original events exactly;
25,418-26,107 still enter the original high-speed branch. Of 447,623-457,873
collision bone-0 profile requests, 421,515-432,297 setter calls are omitted
(94.2-94.4%). Only 11-12 requests change the authoritative override name.
There are no unapplied requests or fallback callbacks in these runs. More frames
produce more callbacks than observe: no fixed event-count reduction is claimed.
Counters end on the first tick at/after five seconds (native 5.004905-5.008332 s),
whereas frame statistics use exact [0,5). These counters exclude break profile
writes; an applied override is not a count of solver filter submissions or bodies.

Batch warm whole-run change counts 3,931 / 3,857 / 3,847 become 403 / 388 / 413
publications, approximately 89.5% fewer, with complete change accounting.
First-five changes 3,591 / 3,627 / 3,602 become 317 / 326 / 341 publications.
The empty legacy-subscriber workload provides no measured consumer saving.

One traced warm repetition per mode corroborates the mechanism: whole-blast
`DP03_CollisionPolicy` inclusive time falls from 1.467502 s observe to 0.192556 s
native (-86.9%), despite 521,916 versus 752,329 callbacks. Mean cost per callback
falls 90.9%. Original Blueprint collision time falls 0.847093 to 0.077976 s.
The Blueprint-exposed profile-setter scope falls only 0.281225 to 0.246636 s;
its burst cost rises 0.173363 to 0.180314 s. Direct native setter calls lack a
separate matching trace scope. This supports cheaper repeated callback dispatch,
not removal of expensive changed-profile/break work or all filter rebuilds.

Whole-blast `GameThreadWaitForTask` remains 2.197932 / 1.720296 s and
`WaitForTasks` 3.534843 / 5.346978 s (observe/native). No wait-union or dependency
attribution exists; these overlapping values must not be summed or assigned
specifically to Chaos. Trace exporters exit 0 with all expected nonempty tables,
but log memory-tag and GPU-timestamp errors plus unrelated metadata/region
warnings. Memory/GPU trace attribution is excluded. Exact [0,5) trace scope
attribution was not exported. See `trace-attribution01.md` for warnings and limits.

## Correctness and acceptance limits

All six diagnostic captures retain the same ten DP-02 core affected props.
Observe total broken props are 10/10, native 11/11 and slowdown 11/10: stochastic
secondary outcomes are not identical. All 320 matching selected large-piece
markers across the ten core props per phase retain index/volume identity. Source fracture geometry,
damage strength, field delivery, high-speed audio/sleep graph and break callbacks
are unchanged; low-speed callback state and profile behavior are source-matched
and tested. Screenshots retain substantial rubble and visible openings.

Before-blast collision probes match exactly. Of 260 matching post-blast probes
per comparison, 23/21 bullet and 9/9 capsule result classes differ. Among 80 core
bullet probes, clear paths are 22/24 observe versus 29/24 native, and own-prop
obstructions are 40/36 versus 33/31. Openings and useful bullet obstructions
remain, but probe counts do not establish identical cover. All 20 core capsule
center probes stay blocked, frequently starting penetrating: they **do not
prove player traversal or walkability**. Owner playtesting must still accept
movement through openings, cover, subsequent combat, sound and sleep behavior.

Focused automation covers 0.5/200 cm/s branch thresholds, repeated profiles,
external profile overrides, copied IDs, replacement/reset, same-component physics
recreation and subsequent bullet damage with duplicate-shot rejection. Notification
tests cover intermediate-bounds union, revisions/counts, actor order, copied IDs,
pending reset, reentrant callbacks, retired lifetimes and immediate compatibility.

Two controlled slowdown runs use native plus experimental batching to exercise
both changed paths. The harness arms at normal speed, then invokes the existing
0.25 world/rifle/bullet and 0.65 hero slowdown after field spawn. Captures cover
60.002/60.001 real seconds and 15.034/15.000 simulation seconds. Both finish with
valid callback/change accounting; all 26 reset props advance revision/generation
and receive fresh lifetime identity. Normal F7 still refuses slowdown arming.
This is focused regression evidence, not the complete DP-10 gameplay matrix.
