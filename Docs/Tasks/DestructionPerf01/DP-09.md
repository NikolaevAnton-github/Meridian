# DestructionPerf01 / DP-09: reusable authoring presets and validation

Status: **prepared; execution not started**.
Dependencies: DP-03 through DP-08 resolved, including measured retain-current decisions.
Read the [shared scope and measurement contract](../DestructionPerf01Tasks.md).
Plan coverage: [section 7](../DestructionPerf01Plan.md).

## Outcome

Turn the measured pillar result into an authoring standard that a second material/
shape can use without bespoke optimization. Keep final scale limits provisional
until DP-10 verifies them on the agreed hardware and scenes.

## Bounded work

- Publish a template and large/medium/small debris presets for fracture hierarchy,
  meaningful rigid pieces, collision complexity, simultaneous release, material
  slots, presentation events, lifetime and retained gameplay rubble.
- Derive numerical limits from the resolved candidates' measured load sweeps;
  run a narrowly scoped missing sweep if necessary. Name the hardware, build,
  graphics and workload for every budget instead of presenting universal quotas.
- Add inexpensive content checks for missing lifecycle settings, excessive
  configured/measured complexity, unbounded effects, duplicate adapter IDs,
  unsupported reset and missing source/derivative provenance. Static metadata
  cannot certify actual runtime cost; retain representative runtime validation.
- Apply the template to one other representative stock destructible material/
  shape through a versioned derivative; preserve sources and approved appearance.
- Provide the authoring checklist and reusable fixed-blast procedure. Record the
  settings/interfaces adopted from DP-03 through DP-08 in one accessible reference.

## Acceptance and focused verification

- The template states how gameplay-critical rubble is identified and retained;
  tiny cosmetic pieces cannot silently replace useful blocking or cover.
- A second asset follows the presets and passes focused damage/collision/reset
  checks with its own measured performance evidence and visual limitations.
- Validation demonstrably identifies representative invalid settings while valid
  retained assets pass applicable checks; runtime-only claims remain separate.
- Document unresolved target-PC or design decisions. Candidate quality remains
  subject to owner testing; the template is not final production acceptance.
